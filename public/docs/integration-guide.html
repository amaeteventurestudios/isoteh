Integration guide

Ask a question

The full process to add Isoteh ads to a site, a newsletter, an app or a game, from picking the spot to getting paid. For the short version, see the owner quickstart.

#Before you start

  • You have an Isoteh account set to Owner. See the owner quickstart.
  • You can edit the page, template, email or code where the ad will go.

#Process overview

  1. Design

    Decide where ads go and how many. One ad near the top of an article and one in the middle of a newsletter is plenty for most places.

  2. Create the spaces

    Add each spot as a space in the dashboard, with its size and price. Each gets an id like sl_8f2k….

  3. Integrate

    Paste the code for your kind of place (below). The dashboard shows the same code with your own ids.

  4. Test

    Open your page. You should see your house ad or the Advertise here card. Check the dashboard: the space shows its first serve within a minute.

  5. Go live

    Make the space bookable and, if you like, join the network so campaigns can fill unsold days.

  6. Approve and get paid

    Approve bookings as they arrive. Money moves to your balance after each booking has run.

#Pick the code for your place

PlaceWhat you pasteGuide
Website or blogA div and one script lineWebsites and blogs
WordPressA shortcode, after a 40-line pluginWordPress
NewsletterAn HTML block with the issue nameNewsletters
App or chatOne function call, drawn in your own styleApps and chat
Three.js gameA billboard meshGames
Any other engineA JSON request and two linksAny engine
Creator channelNothing: share your booking pageCreators

#Use the SDK or the API

Use an SDK when you want the view counting done for you. The website script, the native SDK and the game SDK all measure what is really on screen and send the view once.

Use the API when you draw everything yourself, for example in Unity, Godot or a server-rendered page. You call GET /v1/ad and then call the view link once the ad has been seen. You are then responsible for the view rule.

Never count a view the reader did not see. Views counted against the rule are found in review, and those bookings can be refunded to the brand.

#Examples

#Website

HTML
<div data-isoteh="sl_your_slot"></div>
<script async src="https://isoteh.amaete.com/s/isoteh.js"></script>

#App or chat

JavaScript
import { getNativeAd } from 'https://isoteh.amaete.com/s/isoteh-native.mjs';

const card = await getNativeAd({ server: 'https://isoteh.amaete.com', slot: 'sl_your_slot', keywords: 'coffee, austin' });
if (card) {
  show(card);      // your own component, with card.label ("Sponsored") on it
  card.seen();     // once it has been half on screen for a second
}

#Three.js game

JavaScript
import { AdBoard } from 'https://isoteh.amaete.com/s/isoteh-three.mjs';

const board = new AdBoard(THREE, { server: 'https://isoteh.amaete.com', slot: 'sl_your_slot', width: 8, height: 4 });
scene.add(board.mesh);
// every frame
board.update(camera, renderer, dt, { occluders: [buildings] });

#When something goes wrong

What you seeWhyFix
Nothing showsNo booking, and the space is set to show nothing when emptyTurn on a house ad or the Advertise here card
The page jumps when the ad loadsThe box has no sizeGive the div a width and an aspect-ratio, or set the space's size
Views stay at zeroThe ad is below the fold and nobody scrolls to it, or your app never calls seen()Move the space up, or call seen() after a second on screen
404 No such slotThe id is wrongCopy the code again from the dashboard
429 Slow downToo many requests from one place for one spaceAsk once per page view, not in a loop
