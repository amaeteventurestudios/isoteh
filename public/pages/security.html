Security

How we protect Isoteh, the people who use it and the money that moves through it.

Last updated 6 November 2026

Built to need lessAds can't carry codeInfrastructureEncryptionAccountsPaymentsHow we buildReport a vulnerabilityContact

#Built to need less

The safest data is data we never collect. Ad requests carry no reader identifiers, abuse limits use a daily-changing hash kept only in memory, and events carry a reference to the ad, not the person.

#Ads can't carry code

Ads are images or plain text. Each image is checked by its bytes, stored under its own hash and served from our address with a fixed type and a strict content policy, so an ad can never run a script on an owner's page.

#Infrastructure

Isoteh runs on Oracle Cloud in the United States behind a hardened web server with automatic TLS. The service runs as its own unprivileged user. Data is backed up every night.

#Encryption

TLS on every connection. Passwords are hashed with a slow, salted hash. API keys and session tokens are stored only as hashes.

#Accounts

Two-step sign-in, team roles, sessions that expire, and limits on repeated sign-in attempts.

#Payments

Card details go straight to Stripe and never touch our servers. Payment webhooks are checked by signature and by amount. Every movement of money is written as a set of ledger rows that must sum to zero.

#How we build

Every change runs the test suite before it ships, and the server uses no outside code libraries, so there are none to patch. Secrets live in the server's environment, never in code.

#Report a vulnerability

Email support@isoteh.amaete.com with the subject Security report and how to reproduce it. Please give us time to fix it before telling others, and don't test against other people's accounts or data. We will answer quickly and credit you if you like.
